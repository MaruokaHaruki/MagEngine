# MagEngine 改修仕様

## 制作エディターの具体化（2026-11-09）

MP-01・MP-02・MP-05は[承認済み設計](../superpowers/specs/2026-11-09-editor-foundation-design.md)に従い初期実装中。Object3dの編集文書・安定ID、配置・設定・保存、Undo、再生用データ分離、手動変更だけの選択反映を対象とする。操作と未確認事項は[操作ガイド](MagEngine_07_エディター操作ガイド.md)を参照。GPUと画面操作、通常のDebugビルド、別フォルダ実行、Hosted CIはCPU検証と分けて扱う。

この文書は2026-11-05のコード調査に基づく目標仕様である。層分離に伴いME-08・ME-09の実行基盤を整備したが、各項目全体の完了を意味しない。個別の状態と履歴を確認する。前回レビューの番号1〜11をME-01〜ME-11へ引き継ぐ。

現状の根拠はリポジトリ相対パスと関数名で示す。実装開始時には最新コードと呼び出し元を再確認する。

2026-11-05追記：ユーザーの指定により、現行構成はMagEngineとGameの2プロジェクトとする。独立したTest／Minimal／Coreプロジェクトは廃止し、元からある検証ソースは保持する。過去のテスト結果は当時の構成の証跡として履歴に残す。

## ME-01 WAV読み込み境界と再生失敗処理

- 状態／優先度：実装済み・CPU／無音API検証済み／High。段階A。
- 改修前の根拠：`engine/audio/MAudioG.cpp` の `LoadWav()`、`PlayWav()`。fmtサイズを固定領域へ直接読み込み、data探索にストリーム失敗判定がない。読み込み失敗後も再生側がoperator[]で空データを登録する。
- 仕様：ヘッダー、各チャンク長、残りデータ、読み込み結果を検証する。未知チャンクはRIFFの2バイト境界を考慮してスキップし、EOFで必ず終了する。固定領域より大きいfmtを直接書き込まない。
- 対応形式：同梱WAV9件はすべてfmt長16、16bit・ステレオ・44.1kHzの整数PCM。整数PCMの8/16bit・モノラル/ステレオ、fmt長16または18（cbSize=0）に対応する。圧縮・浮動小数点・拡張形式は拒否する。チャンク境界、PCMブロック長・毎秒バイト数、XAudio2のレート・バッファ長上限を検証する。
- 失敗契約：現在のvoid APIは維持し、理由を記録して再生しない。再生側は初期化済み状態とロード成功を再確認し、読み込み失敗時にキャッシュを登録しない。再生API失敗時は新しいVoiceを残さず、有効に読めたキャッシュは保持する。ソースボイス作成失敗も後段へ進めない。
- 影響：MAudioGのヘッダー・実装、全LoadWav／PlayWav／PlayWavReverse呼び出し元、同梱WAV、音声回帰fixture、テスト登録。
- 完了条件：短いヘッダー、fmt過大、data欠損、奇数長の未知チャンク、途中切断、未対応形式を安全に扱う。失敗後の再試行で空キャッシュが残らない。正常素材の読み込みテストと実音声確認を分けて記録する。

## ME-02 モデル読み込みの失敗契約

- 状態／優先度：実装済み・CPU検証済み・画面描画は未確認／High。段階A。
- 改修前の根拠：`engine/render/resource/model/Model.cpp` の `LoadModelFile()`、`Initialize()`。scene、法線、UV、三角面の確認がassertに依存する。
- 仕様：読み込み失敗、メッシュなし、法線・UV欠損、不正な頂点参照、非三角形面はReleaseでも検出し、ファイル名と理由を含む例外で初期化を中断する。初期対応ではUV生成・法線生成・自動三角形化を追加しない。
- 失敗契約：CPU側の検証が通るまでGPUバッファを生成せず、ModelManagerへ登録しない。マテリアル参照と描画に必要なdiffuseテクスチャ名、頂点ビュー容量も検証する。GPU生成・Map・テクスチャ読込まで一時所有者で行い、成功後に公開する。生成済みモデルへの再初期化はGPU参照を壊すため拒否する。既存の正常な三角形モデルと複数材質時の従来の選択方式は維持する。
- 影響：Model、ModelManager、モデル読み込み呼び出し元、正常／不正モデルfixture、テスト登録。
- 完了条件：存在しないファイル、メッシュなし、法線なし、UVなし、四角面を明確なエラーで拒否する。正常モデルの頂点数・テクスチャと描画を確認する。モデルパーサを検証できる最小のCPU境界を使い、GPU初期化をCPUテストへ持ち込まない。

## ME-03 逆再生データの寿命と反転単位

- 状態／優先度：実装済み・CPU／無音API検証済み／High（API使用時）。段階A。通常経路の呼び出しは調査時に未検出。
- 改修前の根拠：`engine/audio/MAudioG.cpp` の `PlayWavReverse()` と `MAudioG.h` の `Voice`。ローカルvectorを送信し、全バイトを逆順にしている。
- 仕様：ME-01で受理したPCMについて、nBlockAlign単位の音声フレームを逆順にする。フレーム内のバイト順・チャンネル順は維持し、データ長がフレーム長の倍数でない場合は拒否する。
- 寿命：反転バッファはVoice等の明確な所有者が保持する。StopWav、再生置き換え、FinalizeではDestroyVoiceによって参照が終了してから解放する。ループ再生中も保持する。
- 影響：Voice、逆再生、停止・再生置き換え・終了処理、PCM反転テスト。
- 完了条件：16bitモノラル／ステレオの既知パターンでフレーム反転を確認する。関数復帰後の再生、ループ、停止、置き換え、終了で寿命を確認し、正常／逆再生のAPI挙動を混同しない。

## ME-04 パーティクル追加数と上限

- 状態／優先度：実装済み・CPU／WindowなしD3D12検証済み・実操作未確認／Medium。段階B。
- 改修前の根拠：`engine/graphics/particle/Particle.cpp` の `Emit()`。既存数を今回のcountと比較している。敵爆発と弾の消滅から呼ばれる。
- 仕様：countは今回の追加要求数。上限はグループごとのkNumMaxInstance。追加数は要求数と残容量の小さい方とし、count=0、満杯の場合は追加しない。既存数が上限以上でも符号なし減算のアンダーフローを起こさない。
- 影響：Emit、EnemyBase／EnemyBullet／ParticleEmitter、発生数境界テスト。呼び出し側の演出数は今回変更しない。
- 完了条件：空、20個残存時に20個追加、上限直前、満杯、上限超の要求を直接確認する。ゲーム内で同時・連続爆発の演出を確認する。

## ME-05 パーティクル名の検証

- 状態／優先度：実装済み・CPU／WindowなしD3D12検証済み・実操作未確認／Medium。段階B。
- 改修前の根拠：`Particle.cpp` の `Emit()`、`CreateParticleGroup()`。文字列リテラルのassertと、materialFilePathによる重複判定がある。
- 仕様：Emitの未登録名はfindで検出し、理由を記録して何も生成しない。空のグループを自動挿入しない。CreateParticleGroupの重複名は確保前にキーで検出し、理由を記録して既存グループを維持する。
- 影響：Particle、グループ作成呼び出し元、名前の異常系テスト。公開void APIは維持する。
- 完了条件：未登録名でグループ数が変わらない。同名再作成で既存内容とDescriptor残量が変わらない。正常名と同じテクスチャを使う別名の作成は成功する。

## ME-06 パーティクルの時間と更新責任

- 状態／優先度：実装済み・CPU／WindowなしD3D12検証済み・実操作未確認／Medium。段階B。
- 改修前の根拠：`Particle.h` の kDeltaTime、`Particle.cpp` の `Update()`、`ParticleEmitter.cpp` の `Update()`、`scene/publicScene/GamePlayScene.cpp`。粒子本体は常に1/60秒を使用し、Emitterも共有Particleを更新する。
- 仕様：Updateへ秒単位のdeltaTimeを明示的に渡す。ゲーム内粒子は既存のgameplayDeltaTimeに従い、ポーズ時は時間を進めず、スロー時は比例して進める。UI等で実時間進行が必要な場合だけ呼び出し側でunscaledDeltaTimeを選ぶ。
- 更新責任：Scene等の所有側がParticle全体を1フレーム1回更新する。Emitterは発生タイミングだけを管理し、共有Particle全体を更新しない。deltaTime=0でも描画データを当該フレーム用に再構築できるようにする。
- 互換性：引数追加は全呼び出し元を同時更新する。固定1/60秒のデフォルト引数は追加しない。これは明示的なAPI変更として記録する。
- 影響：Particle、ParticleEmitter、全Update呼び出し元、ポーズ・スロー経路、時間進行テスト。
- 完了条件：同じ総時間の30／60／120回更新で寿命進行が一致し、移動差が事前に定めた積分誤差内になる。ゼロ時間、ポーズ、スロー、複数Emitterでも二重更新や描画インスタンスの累積がない。

## ME-07 複数マテリアルモデル

- 状態／優先度：条件付き未着手／機能改善。段階D。
- 根拠：`Model.cpp` の `LoadModelFile()`、`Draw()`。頂点を統合し、単一のmaterial.textureFilePathを最後のメッシュで上書きする。
- 仕様：採用するモデルで必要性が確認されたら、メッシュの頂点範囲とマテリアルを保持し、範囲ごとに対応テクスチャで描画する。単一マテリアルモデルの既存経路を維持する。
- 着手前の決定事項：テクスチャなしマテリアル、ChangeTextureが全体／一部のどちらを変えるか、材質パラメータ共有の扱い。必要な利用例を確認し、曖昧なまま実装しない。
- 影響：Modelのデータ構造・読み込み・描画・ChangeTexture、ModelManagerと利用側、2材質モデルfixture。
- 完了条件：2つの異なるテクスチャを持つモデルを正しく描画し、既存単一モデルとテクスチャ変更の回帰がない。

## ME-08 CI成果物の収集

- 状態／優先度：実装済み・Hosted CI検証待ち／Medium。段階C。
- 根拠：`MagEngine.vcxproj` のOutDirは `$(SolutionDir)..\generated\outputs\$(Configuration)\`。`.github/workflows/DebugBuild.yml`、`ReleaseBuild.yml` は `**/x64/<構成>/` を収集している。
- 仕様：本体出力先を維持し、CI側でGitHub workspaceを起点に解決した実出力先を収集する。上位フォルダに出るため、単にworkspace内のgeneratedへ置き換えない。Release添付も同じ出力契約に揃える。
- 配布契約：実行に必要なDLLとresourcesを確認し、利用可能な成果物として配置する。ビルドだけのArtifactなら、その用途を明記する。作業フォルダ依存の相対パスも確認する。
- 影響：Debug／Release workflow、Artifact／Releaseの収集設定、READMEの必要箇所。コード・出力先の一括変更は行わない。
- 完了条件：両CIで成果物が空でないこと、対象exe・必要DLL・必要資産を確認する。別の展開先での起動確認を別に記録する。タグReleaseはトリガー条件も確認し、公開・タグ作成はこの仕様策定では行わない。

## ME-10 CPUとGPUの並行処理

- 状態／優先度：保留／性能改善。段階E。
- 根拠：`engine/base/core/DirectXCore.cpp` の `EndFrame()` はSignal直後に同フレームのFenceを待つ。即時リソース解放を安全にする意図がコメントにある。
- 着手条件：CPU／GPU待機の計測で効果が見込めること。リソース・Descriptorの破棄箇所、mapped bufferの更新箇所、フレーム別領域を先に一覧化する。
- 仕様：Fenceに基づく遅延解放、フレームごとの書き込み領域、終了・シーン遷移時の待機を揃えた後に、同フレームの即時待機を外す。待機だけの削除は禁止する。
- 影響：DirectXCore、FrameContext、GPUリソースを更新・破棄する全経路、Descriptorの再利用、シーン遷移と終了。
- 完了条件：同条件でCPU／GPU時間を比較し、Debug Layerの不正アクセス・状態エラーがない。大量生成・削除、シーン遷移、終了を含む検証結果が揃う。改善がなければ導入を見送る。

## ME-11 テクスチャ転送用バッファの解放

- 状態／優先度：保留／メモリ改善。段階E。
- 根拠：`TextureManager.cpp` の `LoadTexture()` はinterMediateResourceをTextureDataに保持し、`DirectXCore.cpp` の `UploadTextureData()` が転送コマンドを記録する。
- 着手条件：転送コマンドの送信とFence値を追跡できること。ME-10と同時である必要はないが、先に同じ寿命管理の前提を確立する。
- 仕様：アップロードを実行したGPU処理の完了後に中間リソースだけを解放する。テクスチャ本体とSRVはキャッシュの寿命に従う。コマンド記録直後には解放しない。
- 影響：TextureData、UploadTextureData、コマンド送信・Fence管理、終了と読み込み失敗処理。
- 完了条件：多数テクスチャでメモリ削減を計測し、ロード直後の描画、追加ロード、シーン遷移、終了でGPUエラーがない。

## 2026-11-06 ME-01〜ME-03の改修範囲

- 音声の公開void APIと自動ロードを維持する。失敗は資産名と理由を記録し、新規Voiceを残さない。既存の有効な音声キャッシュはAPI失敗だけでは消さない。
- Voiceが反転データとソースボイスを所有し、停止・置換・終了でDestroyVoice完了後に反転データを解放する。自然終了後のVoiceは次の操作またはFinalizeまで保持する。Unloadで管理中データを解放する場合はVoiceを先に破棄する。
- 音声のデータ／Voice操作を同じmutexで保護する。操作はXAudio2コールバックから呼ばず、ライフサイクル操作はアプリ側で直列化する。
- Modelの非公開CPU読み込み境界と音声の非公開パーサ／フレーム反転を、限定したfriend検証から直接確認する。独立Testプロジェクトは作らず、生成領域に検証実行ファイルを作る。
- 検証：tests/AssetSafetyTests.cppとscripts/RunAssetSafetyTests.ps1で実装を直接検証する。CPU境界の拒否・再試行、同梱WAV9件とモデル8件、8/16bit・モノラル/ステレオPCM、16bitの既知フレーム反転を確認した。実XAudio2では無音で正常再生と失敗経路、逆再生の寿命を確認した。最新結果は履歴参照。
- 画面検証：ゲーム起動の自動操作はユーザーのEscapeにより中止された。今回の起動・GPU描画・終了と実操作は未確認。以前のゲーム動作報告を今回のGPU検証には流用しない。聴感・長時間負荷・Hosted CIも未確認。

## 2026-11-06 ME-04〜ME-06の実装契約

- Particle::Update(float deltaTime)へ秒を必須引数として渡す。負値・NaN・無限大はログを記録し0秒として扱い、描画スナップショットは再構築する。
- GamePlaySceneがポーズ・終端演出・遷移を含む各経路で共有Particleを一度だけ更新する。ポーズは0秒、通常・スローはgameplayDeltaTime、終端演出も最後に有効だったゲーム倍率を継承する。
- Emitterはコンストラクタの即時発生、最初の正時間更新での発生、1更新につき最大1回の周期発生という既存挙動を維持する。ゼロ・不正時間では周期を進めず発生させない。無効な周期（0以下・非有限値）は繰り返しを停止して記録する。固定1/60秒のデフォルトは削除する。
- 移動は既存の半陰的Euler法（重力で速度を更新してから位置を進める）を維持する。初速v・一定重力g・総時間T・N等分なら解析解との差は各軸で |g|*T*T/(2N)。1秒・g=-9.8・N=30/60/120の比較ではN間の予測差とfloatの丸め余裕1e-4以内を判定基準とする。寿命進行の差は1e-5秒以内とする。
- instanceCountはUpdate開始時に各グループで0に戻して構築し、Drawでは消費・更新しない。GPU待機と描画フェーズは維持する。
- 寿命は今回の時間を足してから判定し、その時刻で補間・描画データを構築する。従来の1更新遅れの消滅・補間を修正する。
- グループ重複を依存アクセス・確保より先にキーで拒否する。共通マテリアルはParticle初期化時に一度生成し、別グループ追加で既存GPU資源を置き換えない。既存の粒子数・演出設定は変更しない。
- 画面操作は今回行わないとのユーザー回答を受けた。UIに依存しない直接検証とビルド・文書更新を行い、ゲーム実操作は未確認として記録する。

- 直接回帰検証はtests/ParticleRegressionTests.cppをRunAssetSafetyTests.ps1 -Suite Particleから実行する。Gpu指定ではWindowなしに実D3D12のPSO・リソース・Descriptor・Mapを検証する。描画実行・画面の確認とは区別する。

- 最終結果：全体・エンジン単独Debug／Releaseと、両構成の粒子CPU・WindowなしD3D12直接検証が成功した。実際のゲーム画面操作はユーザー指定で実施していない。ログとObsidian反映状況は履歴の2026-11-06-02を参照する。
