# MagEngine Vectorheartテーマとウィンドウ追従

日付：2026-11-11（日本時間）
状態：方法①と本設計書をユーザーが承認済み。製品コードは今回未変更。

## 目的と合意

Vectorheartをベースに、ユーザーが挙げたWipEout、Ridge Racer Type 4、ACE COMBAT 3のようなシャープでスポーティーな近未来感を、長時間使う制作ツールへ取り入れる。作品のロゴ・素材・固有画面をコピーせず、幾何学的な見出しと整理された情報階層でMagEngineの個性を表現する。

視認性、操作性、既存機能と操作方法の維持を優先。ダークグレー、ライムイエロー、シアンを基本とし、既存の4分類色を維持する。既存ImGuiと描画系を活用し、不要な依存や大規模な作り直しを避ける。

## Approaches

1. ウィンドウ追従：現在のクライアントサイズへ描画解像度を追従させ、中央パネルには画像全体を収める。GPU資源の更新契機がウィンドウ変更に限られ、現行構成を活かしやすい。ユーザー選択案。
2. 中央パネル追従：パネルの組替えでも描画解像度を更新する。表示領域を細かく活かせるが、更新頻度と入力／資源管理が増えるため今回採用しない。

## 現状と制約

WinAppのサイズ取得は1280×720の定数、EditorUiSystemの画像サイズも固定。DirectXCoreは2つのレンダーテクスチャと深度・バックバッファを持ち、Descriptorは単調増加割当。単に生成処理を繰り返すとDescriptorを消費する。TextureManagerにもRenderTexture0／1のメタデータ・ビューがあり、画像だけ交換しても参照が古く残る。

共通スタイルはImguiSetup、分類色はEditorWorkspaceLayoutにある。既存のFirge-Regular、MS Sans Serif Bold等のフォントを再利用できる。現在のGPU待機、RenderWorld／RenderPass／RenderGraphの責務、2プロジェクトとGame→Engineの依存方向を維持する。externalsを変更しない。

## 段階と完了範囲

1. 実サイズ取得・安全な描画資源更新・カメラと入力の整合を完成させる。
2. 共通の色・寸法・フォント・DPI適用を整える。
3. ツールバー・タブ・見出し・選択状態へ限定した装飾を追加する。

新しい描画機能、独立エディタープロジェクト、汎用テーマ編集画面、アニメーションする装飾、外部フォントの追加、マルチモニター用の独立ImGuiウィンドウは含めない。

## ウィンドウと描画資源

初期サイズとして1280×720は残せるが、現在のクライアントサイズを実行時の正本にする。WM_SIZEは最新の要求サイズだけを記録し、ウィンドウプロシージャ内でGPU処理をしない。ドラッグ中の複数要求は次フレームで最新値へまとめる。

最小化・幅0・高さ0では描画とサイズ依存資源の生成を止める。復帰後に正の最新サイズを適用する。同じサイズなら再生成しない。極端な寸法や生成失敗は実行時に検証し、無効な資源のまま後段へ進めない。

GPU完了待ち後、旧バックバッファへの参照を解除し、ResizeBuffers、RTV、深度／DSV、2つのカラー画像、関連SRV、TextureManagerのメタデータ、viewport／scissorを整合させる。既存Descriptorスロットを再利用し、サイズ変更のたびに割当数を増やさない。ポストエフェクトとRenderGraphが参照する実体と初期状態も更新する。

候補のオフスクリーン画像や深度は可能な範囲で交換前に生成する。ResizeBuffers後に復旧できない失敗が起きた場合は、理由をログへ出し、描画を止めて安全に終了する。バックバッファまで旧状態へ戻せると保証しない。フレーム／Fenceと現在のバックバッファ番号を再取得する。

通常ゲームと編集用カメラの縦横比を実際の描画サイズに合わせる。中央画像はその縦横比を保って全体を表示する。クリック選択、軸操作、マウス入力変換は実際の画像領域と最新描画解像度を使い、16:9固定の投影計算も対象内で修正する。

サイズ変更に影響する画面中央、HUD、正射影、ポストエフェクトの画素寸法を計画時に棚卸しし、今回の経路に必要な固定値だけを移行する。全定数の一括置換や無関係な作品ロジックの再設計はしない。ReleaseのUIなし起動にも安全なウィンドウ追従を適用する。

## UIのサイズ・DPI

ドックの分割割合とユーザー保存レイアウトを維持する。サイズ変更で毎回標準配置へ戻さない。狭い幅ではツールバーを折返し、関連操作を既存メニューへ収める。入力欄は列幅へ追従し、ラベルを潰さず、必要ならパネル内をスクロールする。

ツールバーの高さを固定の推測値に頼らず、実際の行数・フォント寸法からドック領域を求める。画像領域が使えない間は選択やゲーム入力を中立にし、直前の矩形へ入力を流さない。

WindowsのプロセスDPI対応とWM_DPICHANGEDを確認し、推奨ウィンドウ矩形と現在DPIを扱う。100%基準のスタイルから倍率を毎回計算し、ScaleAllSizesを累積適用しない。フォントも倍率に対応し、変更時だけGPU待機を伴う既存フォントアトラス更新経路を使う。UIとゲーム画像の座標単位を揃え、二重に倍率を掛けない。

## テーマの提案値と適用箇所

以下は設計者の提案値。実画面でコントラストを確認して微調整する。

- 背景：暗い無彩色の#16191F前後、パネルは#1D222A前後。本文は#DCE2E8前後。細い境界と余白で区切る。
- 主アクセント：ライムイエロー#D7F542。現在の選択、再生ボタン、ブランド見出しの短い線などへ限定する。
- 補助アクセント：シアン#4ED9E8。フォーカス枠や補助的な表示へ使う。
- 所属：制作・エンジン・ゲームデバッグ・ツールの既存分類色を維持。警告・エラー色と役割を分ける。
- 本文は既存日本語フォント。短い英字のMAGENGINE見出し等には既存の太字フォントを使い、日本語グリフがない場合は本文フォントへ戻す。

ツールバーの一角に小さなMAGENGINEの文字と線・円・斜線を使う。見出しや選択タブには短いライム線や45度の切り欠きを添える。装飾はImDrawListの既存図形で描き、画像資産・シェーダー・新しい描画システムを追加しない。

通常入力欄、資産一覧、コードや設定の本文へ模様を敷かない。斜体や大文字を本文へ強制しない。境界や装飾をクリック領域として数えず、操作部品の矩形とラベルを保つ。見出しが狭ければ装飾を省略する。点滅や常時アニメーションは行わない。

色・余白・角・行高・フォント倍率を小さな共通テーマ定義へ集める。所属色もその定義を参照し、別の設定基盤や反射は作らない。SRGBの描画先で実際の明るさが設計色と一致するか確認し、ゲーム画像の色は変更しない。

## 確認と受け入れ

- 1280×720、1600×900、1920×1080、1024×768、800×600で、画像全体・ツールバー・入力欄・保存／再生／配置切替を確認する。
- 素早い拡大縮小、最大化、最小化と復帰、表示倍率100%／150%／200%で破綻や累積拡大がないことを確認する。環境にない倍率やモニターの実機確認は未実施として報告する。
- 同サイズ要求と最小化で再生成しないこと、連続リサイズでDescriptorが増え続けないこと、失敗時に描画を続けないことを直接検証する。
- 更新後のカメラ縦横比、画像の中心と端での選択・軸操作・入力を確認する。ユーザーのドック配置と保存ファイルを保持する。
- 通常ゲーム、編集モード、ReleaseのUIなし起動、既存ポストエフェクトを回帰確認する。Debug／Releaseビルド、既存CPU検証、層境界検査を行う。
- 見出し・タブ・ツールバーには個性があり、本文と作業領域は落ち着いて読めることを実画面で確認する。

## 実装者へ委ねる点と状態

具体的な型名、WinAppへの要求サイズの保持方法、共通テーマの配置場所、狭い幅での折返しのしきい値は既存実装に沿って決める。描画資源の所有者や現在の待機方式は変えない。DPIのmanifest／APIは既存設定を調べ、重複した設定を追加しない。
