# 新作制作前のエンジン専用構成への整理

状態：承認済み設計に従って実装・自動検証を完了。手動の画面操作は未確認。確認条件と結果は仕様・改修履歴を参照。

## 目的と範囲

新ブランチ `Ver2.1.0_Feature_NewGame` で旧ゲームのコードを取り除き、新しいゲーム制作を始められる状態にする。旧ゲームのモデル・音声・テクスチャ・設定等は再利用資産として残す。

## 検討した方式（Approaches）

1. ゲーム固有コードを削除し、エディターと最小の起動アプリを残す。制作画面からエンジンを使い続けられ、現行のMagEngine／Gameの2プロジェクトを維持できる。ユーザー選択方式。
2. 実行アプリも削除し、ライブラリだけにする。構成は小さくなるが、次の制作時に起動アプリを作り直す必要があり、今回は採用しない。

## 残すもの

- `engine/` の描画、入力、音声、共通UI、編集文書等のエンジン機能。
- `application/editor/` の編集ホストと起動引数処理。現在はGame側に置かれているが、旧ゲーム固有コードではないため保持する。今回のためだけにエンジン層へ移設しない。
- `main.cpp` と `application/EngineApp.*` は最小の起動・終了・編集ホスト接続として残す。
- `resources/` 以下は名前・場所・内容を変更しない。旧ゲーム用設定も資産として保持し、自動ロードするゲームコードだけを除く。
- 外部ライブラリ、エンジン／エディターのテスト、ビルドと配布の仕組み。

## 取り除くもの

- `application/` の旧Player、Enemy、ゲーム進行、作品用UI、演出、衝突処理、作品用ユーティリティ等。編集ホストと最小起動処理は除外する。
- `scene/` の旧Scene実装と、それだけが利用するSceneFactory／SceneManager／基底構成。エンジン側に必要な依存がないことを確認してから削除する。
- 削除コード専用のテスト部分、プロジェクト登録、include設定、実行経路からの参照。エンジン共通の検証までまとめて消さない。

## 起動後の状態

実装者の提案：Debugは引数なしでも空の編集文書で制作画面を開く。明示的なシーン指定時だけその文書を読み込み、旧ゲームのレベルや設定は自動読込しない。既存の保存・読込・配置・再生操作を維持する。Releaseは従来どおり制作UIを含まず、最小の描画実行アプリとして起動できる状態にする。

## 制約と確認

大規模なフォルダ改名、新しいゲームの雛形・機能追加、リソース分類変更、生成物の一括削除は今回含めない。既存ブランチのまま作業し、コミットやブランチ操作はしない。

削除対象を実パスで確認し、資産の変更がないことを前後の一覧・ハッシュで確認する。Debug／Releaseのビルド、層境界検査、残したエンジン／エディターの回帰検証、空の制作画面の起動を確認する。環境依存のビルド問題と検証用設定は分けて記録する。
